### abuse.ch terms

The three abuse.ch feeds share one [Terms of Use](https://abuse.ch/terms-of-use/). What it says, as read on 2026-10-07:

- Access is for "Authenticated Users" who completed authentication at `auth.abuse.ch`; the bulk exports above still download without an Auth-Key today, which is how the mirror fetches them.
- "Authenticated Users may access the Platforms for not-for-profit purposes, subject to usage limitations" (Query Volume Limits "reasonably expected for non-commercial or non-profit purposes").
- "Use of the Platforms by companies, networks, or individuals with commercial or for-profit needs may require a paid subscription, which will be managed by Spamhaus."
- The terms do not say whether a company using the data only to protect its own infrastructure counts as for-profit use.

Sparkgeo is a for-profit company and uses the data internally, one download per feed per day. Two follow-ups are tracked in #108 before #110 moves from advisory to blocking:

1. Register an abuse.ch account for the mirror, store its Auth-Key as the `ABUSE_CH_AUTH_KEY` repository secret, and send it as the `Auth-Key` header from `threat-feeds-mirror.yml`, so the mirror keeps working if anonymous exports are withdrawn.
2. Ask abuse.ch / Spamhaus whether internal defensive use by a for-profit company at this volume falls under fair use, and record the answer here. If a subscription is required and declined, drop the three abuse.ch feeds from the mirror; KEV and EPSS are unaffected.

## IOC expiry policy

Implemented in [`normalize.py`](../.github/actions/threat-feeds/normalize.py) (`EXPIRY_DAYS`). The mirror drops expired entries before publishing and reports them as `dropped_count`; consumers never see a stale indicator.

| Type | Expiry | Clock starts at | Rationale (plan Step 27, IOC Lifecycle Policy) |
|---|---|---|---|
| `ip` | 30 days | `last_seen` if the feed has it, else `first_seen` | IPs are reused or reassigned quickly; staleness risk is high. A C2 IP today may be a CDN node in 90 days |
| `url` | 60 days | same | URL paths change; the domain may persist but the path becomes a 404 |
| `domain` | 90 days | same | Domains persist longer than IPs but still rotate |
| `cve` | never | n/a | A KEV entry or an EPSS score describes a vulnerability, not infrastructure; it stays true |
| `cidr` | 30 days | same | Reserved for feeds that publish ranges; none of the current five do |

**Changing a value.** Edit `EXPIRY_DAYS`, update the expected `expires_at` dates in `tests/threat-feeds/run.sh`, and record the reason in the quality log below. Longer windows are the usual temptation after a missed match; resist them unless the log shows the indicator was still live when it expired. A longer window raises the false-positive rate on every consuming PR (a reassigned IP in a security group rule becomes a blocking finding), and the plan's numbers already err on the side of keeping an indicator too long rather than too short.

**Entries with no date.** Kept, never expired. None of the current feeds omit dates; if one starts to, the mirror's day-over-day drop check will not catch it, so review `dropped_count: 0` on a feed that previously expired entries.

## Quality log: true positives per feed

The plan's rule: "Measure each feed's true positive rate against your environment before keeping it." Recorded here quarterly from the consuming workflows' findings (#110 annotations, #80 uplifts), with the two decision rules below applied at the end of each quarter.

| Quarter | Feed | Matches in Sparkgeo repos | True positives | Noise rate | Decision |
|---|---|---|---|---|---|
| 2026 Q4 | CISA KEV | | | | first quarter; no decision |
| 2026 Q4 | EPSS | | | | first quarter; no decision |
| 2026 Q4 | ThreatFox | | | | first quarter; no decision |
| 2026 Q4 | Feodo Tracker | | | | first quarter; no decision |
| 2026 Q4 | URLhaus | | | | first quarter; no decision |

A match is a finding emitted by a consumer. A true positive is a match that was a real indicator in the repo (not a reassigned IP, a sinkhole, a documentation example or a test fixture). Noise rate is `1 - true positives / matches`.

Decision rules:

- **Zero true positives over two consecutive quarters: drop the feed** from the mirror and from this table. A feed that never matches costs a download and a false-positive risk for nothing.
- **Noise rate above 50 percent in a quarter: demote the feed to advisory** in every consumer (remove its categories from `block-on` defaults in #110) until a quarter shows it below 20 percent.
- **Adding a sixth feed** needs a quarter of advisory-only results recorded here first. Five curated feeds beat twenty noisy ones (plan Step 27, feed quality note).

## Graduation to MISP (plan Standard tier)

The mirror is the Baseline-tier answer: raw feeds, one normalisation step, no platform. The plan's Standard tier deploys MISP (ingestion, deduplication, scoring, distribution to a SIEM). Graduate when both hold:

1. A SIEM exists (plan Step 9) that can receive indicators from MISP; without a receiver a TIP distributes to nothing.
2. A named owner reviews new IOCs and false positives weekly (2–4 hours a week per the plan). The quality log above has been kept for at least two quarters, so the owner starts with evidence, not guesses.

When met: MISP ingests the five feeds through its own feed connectors, and the mirror's snapshot becomes one more MISP input (MISP's JSON feed importer reads the envelope). Consuming workflows keep reading the mirror; nothing in CI changes. The expiry and scoring policy moves into MISP, and this file records that the mirror's `EXPIRY_DAYS` mirrors MISP's decay model rather than defining it. If MISP later publishes a curated set that outperforms the raw feeds in the quality log, the mirror switches its sources to MISP's export and the composite contract stays the same.

## Consumers

| Consumer | Feeds | How |
|---|---|---|
| #80 EPSS and KEV override | `kev`, `epss` | `threat-feeds` with `feeds: kev,epss`; uplift to Critical when the CVE is in `kev.json` or has `meta.epss >= 0.10` (input `epss-threshold`); annotate with the EPSS score and KEV `first_seen` |
| #110 IOC check | `threatfox`, `feodo`, `urlhaus` | `threat-feeds` with the `feeds-ref` input passed through as `ref`; indicator categories map to `block-on`: `c2-ip` (ThreatFox `ip`, Feodo), `c2-domain` (ThreatFox `domain`), `malware-url` (ThreatFox `url`, URLhaus). Default is advisory (empty `block-on`) until the quality log supports blocking |
| #111 dependency reputation | none | live per-package queries to deps.dev and the Scorecard API; not feed data, so outside the mirror rule |

Rule for new consumers (CONTRIBUTING, workflow authoring checklist): any workflow that needs external intelligence reads it from the mirror through the composite. No workflow fetches a feed host directly; the mirror job is the only allowlisted path to them ([`docs/egress-allowlist.md`](egress-allowlist.md)).
